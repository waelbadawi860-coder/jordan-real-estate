Scope: the five-area QA matrix (listing lifecycle, roles, promotions, search/map/caching, admin control), run against the development database and the staging site `aqar-staging.vercel.app`.

New automated tests: `web/tests/db/qa.test.ts` (16 tests). All suites after the fixes:

| Suite | Result |
|---|---|
| Unit | 51/51 pass |
| Database (includes the 16 new QA tests) | 113/113 pass |
| Site tests on the local dev server | 52/52 pass (before this QA round) |

Result key: **Pass** = works as the matrix expects. **Fixed** = gap found and fixed in this round. **Finding** = works, but differs from the matrix; owner decision. **N/A** = the feature doesn't exist yet.

## 1. Listing lifecycle

| Check | Result | Evidence |
|---|---|---|
| Edit after approval (price/description) | **Pass** | Ad goes back to "pending approval" and disappears from the public site immediately. |
| Max photos per ad (20) | **Pass** | The 21st photo is refused (`image_limit_reached`). |
| Oversized file (> 5 MB) | **Pass** | Refused by storage. |
| Non-image files (PDF, script) | **Pass** | Refused by storage type. A file faked as an image is checked byte by byte and never copied to the public bucket. |
| Withdraw/delete → feed, dashboards, favourites | **Pass** | Gone from the feed and search; another user's favourite no longer returns it. |
| Admin hold/reject → feed | **Pass** | Gone immediately (also on staging, see 4.1). |
| Several reports on one ad | **Pass** | Each report is kept; the admin sees the count per ad. |
| Automatic hiding after N reports | **Fixed** (owner approved) | When 3 *different* signed-in users report the same live ad within 24 hours, it is put on hold, its photos and pages come down at once, and the admins and the seller are notified. An admin can release it unchanged. Visitors who aren't signed in don't count, and one account can't report twice. The number is in Settings (0 = off). |

|---|---|---|

| Check | Result | Evidence |

| Expiry at the exact moment | **Fixed** | The database stops counting it as featured the second it expires. Cached lists now expire at the moment the first featured ad on them ends: measured on a production build, the "featured" label was gone within 1 second. |

# The five mandatory checks (30–31 October 2026)

| # | Check | Result | What was done |
|---|---|---|---|
| 1 | **Security audit** (RLS, private photos, verification documents, direct API calls) | **Pass** | The attack script now tries **89** things as a visitor and as a signed-in user, all refused. Examples: reading phone numbers, consents, reports, risk signals, saved searches, the admin indicators and verification documents; writing consents or saved searches for others; calling admin functions; downloading private photos and documents. Plus 116 database tests on access rules. |
| 2 | **Backup and restore** | **Ready, waiting for 2 GitHub secrets** | The daily encrypted backup on GitHub now has an automatic **restore test**. Every backup is restored into a fresh copy of Supabase's database (same version, 17.11), and the rows in each table are compared with the live database. If the restore fails, GitHub e-mails the owner. It starts working once `SUPABASE_DB_URL` and `BACKUP_PASSPHRASE` are added (docs/OPERATIONS.md). On the production account, Supabase's own daily backups add a second copy. |
| 3 | **Speed on a mid-range phone and a weak connection** | **Pass** | Lighthouse, mobile mode (mid-range phone, slow 4G): home 97, search 98, ad page 99. Accessibility 100 on all three. On very slow 3G (400 kbps, real throttling) the main content shows in 3.5 s on the home page and 5.0 s on search. Pages weigh about 350–400 KB. |
| 4 | **SEO** | **Fixed + Pass** | Area pages weren't indexable: every search pointed to `/search`. Now each "deal + type + governorate (+ area)" page has its own address, title and description, for example «شقة للبيع في عبدون، عمّان», and is listed in the sitemap while it has ads (118 addresses on the test data). Searches with extra filters point to that page and aren't indexed, and empty pages aren't indexed. Removed, expired or sold ads return a real 404 and leave the sitemap. The test copy is never indexed. |
| 5 | **Monitoring** | **Built** | Server errors, failed photo uploads (including failures in the visitor's browser), photos refused for publishing, failed ad saves and failed scheduled jobs are recorded without personal data. They appear on the admin dashboard ("Failures, last 24 hours") and are kept 30 days. More than 10 failures in 15 minutes send the admins **one** notification per hour (the number is in Settings). Still to add at launch: UptimeRobot on `/api/health` (free, needs the owner's account), and e-mail alerts once the domain and e-mail sender exist. |
